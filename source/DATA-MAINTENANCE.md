# تحديث الخدمات بأمان

البيانات الأصلية: services-data.json. لا توجد لوحة إدارة عامة أو تعديل مباشر من المتصفح؛ تحديث المصدر ثم البناء والنشر هو المسار الحالي. ملفات Excel الأصلية وخريطة SERVICES-SOURCE-MAP.json محفوظة للرجوع إلى النسخة الأولى.

1. حضّر نسخة JSON جديدة من services-data.json. احتفظ بمعرّفات الخدمات الحالية، وأضف معرفًا فريدًا للخدمات الجديدة.
2. استخدم التصنيفات الثلاثة الحالية: investors وgeneral وmarketing. تظهر في الصفحة الرئيسية ودليل الخدمات تلقائيًا.
3. title اسم الخدمة الرئيسية، provider الجهة أو المنصة، description النبذة، details قائمة الخدمات والإجراءات المشمولة، category معرّف التصنيف، type وصف نوع الخدمة. active: false يوقف عرض الخدمة دون حذف سجلها. sourceIds يربط الخدمات الحكومية ببيانات الدليل الأصلي في services-original.json.
4. priceSAR اختياري، يقبل null أو رقمًا موجبًا بمنزلتين عشريتين. لا يفعّل الدفع ولا يعرض سعرًا تلقائيًا؛ الأسعار تبقى قيد المراجعة حتى تجهيز التسعير والضرائب والدفع.
5. شغّل node update-catalog.mjs --check candidate.json للفحص فقط.
6. شغّل node update-catalog.mjs --apply candidate.json لاعتماد الملف محليًا؛ تُنشأ services-data.backup.json، ثم يستبدل الملف عبر كتابة مؤقتة وإعادة تسمية.
7. شغّل node build.mjs ثم node verify-build.mjs وnode verify-catalog.mjs وnode verify-audit.mjs.
8. راجع الخدمات والتصنيفات المعنية وانشر مجلد dist عبر GitHub Pages. الحفظ المحلي وحده لا يعدل الموقع المنشور.

الأعداد في الصفحة الرئيسية ودليل الخدمات تُحسب آليًا من الخدمات النشطة. الفحص يرفض المعرفات المكررة، التصنيفات المجهولة، النصوص الفارغة أو المحتوية على ترميز HTML، والأسعار السالبة أو غير الصحيحة. لا تضع أي مفاتيح دفع أو بيانات عملاء في ملفات البيانات أو dist.

قبل لوحة إدارة مستقبلية: تسجيل دخول موثوق وصلاحيات على الخادم، سجل تغييرات، نسخ احتياطية واسترجاع، والتحقق من البيانات على الخادم. لا تستخدم رابطًا مخفيًا أو كلمة مرور في JavaScript كحماية للإدارة.
